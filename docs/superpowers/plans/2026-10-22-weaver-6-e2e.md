# Weaver End-to-End, CI and Docs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove every format works with real clients against the production image (publish to hosted, pull
through mirror with cache on and off, read through group, auth/permission denial), run that in CI against
local stand-in upstreams and nightly against real upstreams, and bring compose files, README, docs and
SECURITY.md in line with Weaver.

**Architecture:** `scripts/e2e-smoke.sh` is replaced by `scripts/e2e/`: one `run.sh` that boots
`docker-compose.prod.yml` plus an e2e override (stand-in upstreams, a second Weaver, SeaweedFS for dual
storage, a Docker-in-Docker daemon for the root mirror), seeds both Weaver instances from a JSON spec,
and runs one bash script per format (`proto.sh`, `maven.sh`, `npm.sh`, `docker.sh`, `platform.sh`) that
drives stock clients. `--upstreams=real` swaps the seed spec so mirrors point at Maven Central,
registry.npmjs.org and Docker Hub. A reusable workflow `.github/workflows/e2e.yml` runs it, called by
`ci.yml` (local), `nightly.yml` (real) and `release.yml` (local, gating the image push).

**Tech Stack:** bash (Git Bash on Windows for non-docker formats), Docker Compose v2, buildx, podman, helm,
Maven 3.9, Gradle (wrapper from `gradle-plugin/`), npm/pnpm/yarn classic/yarn berry/bun, Playwright 1.64
(npm web login approval), Vitest 5 + Testcontainers (seed logic), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-22-weaver-design.md`

**Depends on:** plans 0-5 (`2026-10-22-weaver-{0-core,1-proto,2-maven,3-npm,4-docker,5-extras}.md`). Every
flow here exercises code those plans built; this plan adds no protocol code. Plans 1-5 were not yet written
when this plan was; Task 1 Step 1 reconciles their "flows for plan 6" lists with this one.

## Global Constraints

- Product name **Weaver**; no `protoloom` string survives outside `docs/superpowers/**` and git history.
- Identifiers: domain `weaver.slne.dev`, repo `SLNE-Development/weaver`, image `ghcr.io/slne-development/weaver`,
  Gradle plugin id `dev.slne.weaver`, CLI npm package `@slne/weaver-cli` (binary `weaver`), CLI config `weaver.json`,
  workspace scope `@weaver/*`, env vars `WEAVER_*`, headers `x-weaver-*`.
- No compatibility aliases for old names (`scripts/e2e-smoke.sh` and `seed-smoke.mjs` are deleted, not kept as wrappers).
- Keep users only: upgrading from Protoloom drops repositories, artifacts, keys, invites and cleanup policies (docs must say so).
- Repository names are globally unique across formats; `library` is reserved for docker repos.
- Mirror caching is **disabled by default**. Default metadata TTL **1800 s**.
- Groups are read-only; read permission on a group grants read of everything served through it.
- Storage: both `STORAGE_LOCAL_PATH` and `S3_*` may be set; `STORAGE_DRIVER` names the primary (hosted) store.
- Anti-goal: no client may need a special flag or workaround. The e2e scripts use only flags a user of a
  plain-http localhost registry needs (`--plain-http`, `--tls-verify=false`, buildkit `http = true`) and nothing Weaver-specific.
- Every CI run uses **local stand-in upstreams**; only `nightly.yml` contacts real upstreams.
- Third-party actions are pinned to commit SHAs with the release in a comment; reuse the SHAs already in
  `ci.yml`/`release.yml`; add no new third-party action.
- Commit messages: Conventional Commits in English, ending with
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- Every exported function, type and component gets a doc comment saying what it does (repo convention).
- Pin new dependencies and container images to exact versions.

## Review Focus

1. **Tarball / blob / realm URLs that leak the upstream** — an npm lockfile or a Docker token realm pointing at
   `verdaccio:4873`/`registry:5000` instead of Weaver works in CI only by accident; `npm.sh` asserts every
   lockfile `resolved` URL starts with `${URL}/npm/npm-group/` (Task 5), `docker.sh` asserts the
   `WWW-Authenticate` realm starts with `${URL}` (Task 6).
2. **A multi-GB layer through a memory-capped app** — the e2e override caps the `app` container at
   `mem_limit: 1g`; `docker.sh` pushes and pulls a 2 GiB random layer when `E2E_LARGE=1` (always on in nightly)
   and asserts the app was not OOM-killed (`docker inspect -f '{{.State.OOMKilled}}'` is `false`) (Task 6).
3. **Client-local caches hiding a broken mirror** — the "upstream down" phase must not pass because `~/.m2`, the
   npm cache, the Docker image store or Gradle's cache still holds the file; every pull uses a fresh
   `-Dmaven.repo.local`, `npm_config_cache`, `GRADLE_USER_HOME` or a prior `docker rmi` (Tasks 3-6, helper `fresh_dir`).
4. **Reverse proxies with body limits** — self-hosters behind nginx defaults (1 MB) or Cloudflare (100 MB) see
   `docker push`/`mvn deploy` fail with 413; `self-host/compose.md` gives the nginx/Caddy settings and
   `troubleshooting.md` names the 413 symptom; a docs test asserts both strings exist (Task 9).
5. **A config page that drifts from the env schema** — a new variable added in plans 2-5 but missing from
   `self-host/config.md`; `docs.test.ts` parses `apps/web/src/env.ts` and `apps/worker/src/env.ts` and asserts
   every key appears (Task 9).

## Decisions

- **Layout:** `scripts/e2e/{run.sh,lib.sh,proto.sh,maven.sh,npm.sh,docker.sh,platform.sh,compose.e2e.yml,versions.env,repos.local.json,repos.real.json,upstream.json}`,
  fixtures under `scripts/e2e/fixtures/<format>/…` (existing `scripts/fixtures/*` move to `scripts/e2e/fixtures/proto/`).
- **Stand-in upstreams (CI):** docker → `registry:3` with htpasswd (exercises upstream Basic credentials);
  npm → `verdaccio/verdaccio:6` with no uplinks; maven → `dzikoysk/reposilite:3.5` with a `--token e2e:<secret>`
  (it is also a reference Maven server for `mvn deploy`); proto → a **second Weaver** (`upstream` service, same
  image, own database `weaver_upstream` on the same postgres, local storage, no worker).
- **Exact image and client versions** live only in `scripts/e2e/versions.env` (sourced by `run.sh`, passed to
  compose as variables): `REGISTRY_IMAGE`, `VERDACCIO_IMAGE`, `REPOSILITE_IMAGE`, `DIND_IMAGE` (`docker:<x.y.z>-dind`),
  `SEAWEEDFS_IMAGE` (same tag as `docker-compose.yml`), `YARN_CLASSIC=1.22.22`, `YARN_BERRY`, `BUN`, `PNPM` (= root
  `packageManager`). Each is the newest release at least 14 days old when the task is executed, as an exact tag.
- **Root mirror test:** a `dind` service (`privileged`, `network_mode: host`) runs
  `dockerd --registry-mirror=http://localhost:${E2E_PORT} --insecure-registry=localhost:${E2E_PORT} --bridge=none --iptables=false --host=unix:///var/run/dind.sock`.
  Host networking keeps `localhost:${E2E_PORT}` (= `BETTER_AUTH_URL`, the token realm) valid inside it; nothing
  on the runner's own daemon is reconfigured. The stand-in holds `library/weaver-e2e-hello:1`, a name that does not
  exist on Docker Hub, so a pull that bypassed Weaver fails.
- **buildx:** a `docker-container` builder created with `--driver-opt network=host` and a buildkitd config
  `[registry."localhost:${E2E_PORT}"] http = true`; the multi-arch fixture is `FROM scratch` + `COPY`, so no QEMU.
- **Platforms:** `docker.sh` needs Linux (host networking); `run.sh` refuses `docker` on non-Linux with
  `docker e2e needs Linux (host networking)`. proto, maven, npm and platform also run on Git Bash.
- **Dual storage in e2e:** the override adds SeaweedFS and sets `STORAGE_DRIVER=local` plus all `S3_*`; every
  `*-cached` mirror sets `cache.store: "s3"`, and the scripts assert their asset rows have `store = 's3'` and
  hosted rows `store = 'local'`.
- **Repo matrix per format `<f>` ∈ {proto, maven, npm, docker}:** `<f>-hosted` (private), `<f>-public` (hosted,
  public), `<f>-mirror` (cache off), `<f>-cached` (cache on, store s3), `<f>-group` = [`<f>-hosted`, `<f>-mirror`]
  (private). Docker additionally `hub` (docker mirror, `dockerRoot: true`, cache on, **public**: the Docker daemon sends no
  credentials to a registry mirror, so a private root mirror only ever answers it `insufficient_scope`). All other mirrors private.
- **Tokens:** `write` (write on every hosted repo, read on every repo), `read` (read on every repo),
  `group` (read on the four `<f>-group` repos only), `none` (no permissions).
- **"Upstream down":** local mode `compose stop <stand-in>`; real mode sets the format's mirrors `offline`
  (`UPDATE repository SET config = jsonb_set(config,'{offline}','true')`). Expected: `*-cached` keeps serving what it
  cached; `*-mirror` fails with HTTP **502** locally (`upstream_unavailable`) and **404** in real mode (offline miss).
- **npm web login:** `npm login --auth-type=web` runs in the background with stdin from `/dev/null`; the script
  greps the login URL from its output and `scripts/e2e/npm-web-login.mjs` (Playwright, headless Chromium, the
  seeded admin's session cookie) opens it and clicks the button named **Create token** (plan 3's approval page; use
  plan 3's button copy if it differs and note it there). yarn berry's legacy `yarn npm login` needs a TTY prompt, so
  its `PUT /-/user/org.couchdb.user:<name>` exchange is replayed with curl byte-for-byte as yarn 4 sends it.
- **No real-upstream proto:** there is no public Weaver; `nightly.yml` runs maven, npm and docker only.
- **Real upstream fixtures:** `org.apache.commons:commons-lang3:3.17.0`; `is-number@7.0.0` and `@types/semver@7.5.8`;
  `alpine:3.20.3` (as `hub-mirror/alpine`, `hub-mirror/library/alpine` and root `alpine`).
- **CI shape:** `e2e.yml` (`workflow_call`, input `upstreams: local|real`) runs a matrix over the formats, each job
  building the image with `docker/build-push-action` (`load: true`, `cache-from/to: type=gha,scope=e2e`).
  `release.yml`'s `image` job needs the e2e jobs.
- **Seed:** logic in `apps/web/src/test/e2e-seed.ts` (so Vitest's `src/**` include tests it), entry
  `apps/web/scripts/seed-e2e.ts` bundled by esbuild exactly as today; guard env `WEAVER_E2E_SEED=1`.
