# Weaver npm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve npm hosted, mirror and group repositories at `<host>/npm/<repo>/` so that stock `npm`, `pnpm`,
`yarn` (classic and berry) and `bun` install, publish, tag, deprecate, unpublish, audit, search and log in
against Weaver with no client workarounds, and show npm packages in the browse UI.

**Architecture:** A new workspace package `@weaver/npm` exports `createNpmHandler: FormatFactory`, mounted by
the core's `/npm/[...path]` route. It parses the raw `rest` path into a typed route, keeps hosted packuments in
a dedicated `npm_package` table (tarballs are core `asset` rows, versions are core `component` rows), reads
mirrors through the core `MirrorEngine` and merges group members in memory. The browser half of `npm login`
(`/cli-login/<id>`), the browse view and the docs page live in `apps/web`.

**Tech Stack:** TypeScript 6, Drizzle ORM 0.45 on PostgreSQL 17, Next.js 16 route handlers and server actions,
Better Auth 1.7 api-key plugin, tRPC 11, React 19, Vitest 5 with Testcontainers, `tar` 7.5.22 (test fixtures).

**Spec:** `docs/superpowers/specs/2026-10-22-weaver-design.md`
**Depends on:** `docs/superpowers/plans/2026-10-22-weaver-0-core.md` (all tasks), executed after plans 1 and 2.

## Global Constraints

- Product name **Weaver**; workspace scope `@weaver/*`, env vars `WEAVER_*`, headers `x-weaver-*`, log prefix `weaver:`.
- Domain in examples and docs: `weaver.slne.dev`.
- Mirror caching is **disabled by default**. Default metadata TTL **1800 s**.
- Groups are read-only; members are hosted or mirror repos of the same format (no nested groups).
- Read permission on a group grants read of everything served through it.
- Storage reads and writes stream; nothing outside proto bundles is buffered whole in memory (npm exception: see Decisions 4).
- Admin UI stays minimal: a new npm repo needs only name, format, kind; there are no npm-specific hosted options.
- npm never overwrites a published version (`NpmHostedConfig = { redeploy: false }`).
- Tarball URLs in every packument Weaver serves point to Weaver: `${publicUrl}/npm/<serving repo>/<name>/-/<file>`.
- Client quirks are bugs: npm, pnpm, yarn classic, yarn berry and bun must work with only `registry` + token config.
- Commit messages: Conventional Commits in English, ending with
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- Every exported function, type and component gets a doc comment saying what it does (repo convention).
- Pin new dependencies to exact versions, like the existing `package.json` files.

## Review Focus

1. **Private repo tarball auth** — npm/pnpm/yarn only send the nerf-darted `//host/npm/<repo>/:_authToken` to URLs
   under that prefix; every tarball URL in hosted, mirror and group packuments must start with
   `${publicUrl}/npm/<serving repo>/`. Pinned by `tarball urls stay under the serving repo` tests in Tasks 4, 6, 7.
2. **Scoped names in every spelling** — `@scope%2fname`, `@scope%2Fname` and `@scope/name` must reach the same
   package for packument, tarball and dist-tag routes. Pinned in Task 3 (`parseNpmPath`) and Task 4.
3. **Two publishes of the same version at once** (CI retries) — exactly one `201`, the other `409`, and the stored
   tarball is the winner's. Pinned in Task 4 `concurrent publish of one version`.
4. **Compressed upstream responses** — `fetch` decompresses gzip; forwarding the upstream `content-encoding` or
   `content-length` would corrupt audit/search/packument responses. Pinned in Task 6 and Task 8
   `gzip upstream is passed through decoded`.
5. **Same version in a hosted and a mirror member of a group** — the tarball must come from the member whose
   manifest won, or `integrity` fails on install. Pinned in Task 7 `duplicate version uses the earlier member's tarball`.

## Decisions

1. **Storage model:** hosted packuments live in a new `npm_package` table (`document jsonb`, `rev int`), because
   dist-tags, deprecations and tombstones are package-level mutable state that needs a row lock. Each published
   version is also a core `component` (`namespace` = scope without `@` or `''`, `name` = bare name, `version`,
   `metadata` = the version manifest) and its tarball a core `asset` (`path` = `<name>/-/<bare>-<version>.tgz`,
   origin `hosted`, linked to the component) so stats, cleanup (plan 5) and storage accounting work unchanged.
2. **Stored tarball URLs are relative** (`<name>/-/<file>`) and made absolute for the serving repo on every response.
3. **Republish after version unpublish is refused** (like registry.npmjs.org): `document.time[version]` stays as a
   tombstone. Whole-package unpublish deletes the row, so the name and all versions become free again.
4. **Packuments are buffered** to parse, rewrite and merge them: upstream packuments are capped at 128 MiB (larger →
   `502 {"error":"upstream packument too large"}`); publish bodies (JSON with base64 tarball) at 256 MiB (`413`).
   Tarballs always stream. Audit request bodies sent to a mirror are buffered too (16 MiB, larger → `413`), so bulk
   bodies can be filtered and retried on the next upstream.
5. **Mirror packument cache keys:** full and abbreviated packuments are different documents at the same upstream
   path. The core `MirrorFetch` gains `cacheKey` (Task 1); npm uses `<name>/.packument` and `<name>/.corgi`.
6. **Login session secret:** the CLI token is stored encrypted with the server secret key until the CLI picks it up
   once; this needs `FormatDeps.secretKey` (Task 1). Sessions expire after 10 minutes; expired rows are deleted
   lazily on every `POST /-/v1/login`. `doneUrl` carries a separate random poll secret stored only as SHA-256.
7. **Permissions:** publish, dist-tag add/rm, deprecate and unpublish need `canAccess(p, repo, "", "write")`; reads need
   `"read"` (group: `canReadThroughGroup`). Writes to mirror or group repos answer `405` with `allow: GET, HEAD`.
8. **Error body** is npm's `{ "error": "<message>" }`; `401` adds `www-authenticate: Basic realm="Weaver"`.
9. **whoami username** is the token owner's `user.name`.
10. **Search hosted** matches `name`, `description` and `keywords` with `ILIKE`, ordered exact-name first, then by name.
11. **Browse:** hosted repos list `npm_package` rows; mirror repos list cached components (README only when a full
    packument is cached); group repos list their members. Package pages live at `/browse/<repo>/-/npm/<name…>`.
    READMEs are rendered with remark + `rehype-sanitize` (untrusted HTML).
12. **Unsupported npm commands** (`access`, `owner`, `team`, `org`, `star`, `hook`) answer `404 {"error":"not supported by Weaver"}`.
